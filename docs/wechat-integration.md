# 小汐：微信聊天与提醒

调研日期：2026-10-16；本机开发实现：2026-10-17。用户已选择先在电脑开着时使用。

本机文字聊天与提醒渠道已实现并完成隔离验证。尚未扫码绑定、调用真实模型或发送真实微信消息；微信平台兼容与手机收件仍待本人验收。

## 使用方式

1. 退出原开发进程后，使用项目根目录的 `启动小汐.cmd` 打开当前开发版。已有安装包未更新。
2. 在「连接与设置」配置并保存模型连接，然后在「微信」中点击「连接微信」。
3. 使用本人微信扫码并在手机上确认；需要时填写手机显示的验证码。该账号能否连接，仍须实际扫码验证。
4. 在微信对应入口先发送一条文字，检查小汐能否回复。
5. 需要提醒时，开启「到期提醒同时发送到微信」，设置一条短时提醒，并在手机上确认实际收到。

微信连接和提醒开关独立保存，不需要再点击页面底部的模型「保存设置」。可暂停连接或解除绑定。退出小汐或电脑关机后停止工作；恢复后不将停用期间的旧提醒全部补发。

## 选择的渠道及限制

腾讯提供了支持扫码登录、收发消息的 OpenClaw 微信插件和协议说明，可以作为微信 ClawBot / iLink 接入的参考。[腾讯项目说明](https://github.com/Tencent/openclaw-weixin/blob/main/README.zh_CN.md)

本轮直接在现有 Python 后端实现渠道适配器，复用对话、工具、记忆和提醒，只支持绑定本人的文字单聊。官方插件本身依赖 OpenClaw，本实现没有安装 OpenClaw，也没有替换现有 Agent。适配器使用自身版本及 `Xiaoxi` 观测标识；服务器是否接受该客户端需要实测。

主动提醒存在渠道限制。腾讯协议说明明确指出，客户端字段和行为不代表完整服务端契约，客户端在缺少上下文时继续发送也不证明服务端会接受。[腾讯协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)

PushPlus 的渠道文档记录了先主动发消息、每发送 10 次或间隔 24 小时需要重新主动对话的限制。这是该接入服务记录的渠道行为，不能当作小汐已验证的固定平台规则。[PushPlus 渠道说明](https://pushplus.plus/doc/channel/clawbot.html)

腾讯仓库有用户报告会话上下文过期导致定时发送失败；这属于故障报告，不是正式的时效承诺。[故障报告 #225](https://github.com/Tencent/openclaw-weixin/issues/225)

因此，本版适合先验证聊天和有效会话内的提醒，不能承诺长期不交互也总能收到消息。云端运行可以解决电脑关机问题，不能解除渠道发送限制。若需要几天不聊天也收到通知，应另外比较通知渠道及其账号资格、发送规则和实测结果。[腾讯企业微信接入说明](https://cloud.tencent.com/act/pro/wecom)

## 已实现的行为

- 默认关闭。点击连接才向微信申请二维码；本人扫码确认，支持二维码过期、验证码及受信任的微信域名跳转。
- 登录令牌和会话上下文保存在现有 Windows 凭据存储中；普通设置、状态接口和错误信息不返回这些凭据。
- HTTPS 长轮询接收消息，校验绑定本人，忽略其他发送者和群聊。按账号和消息编号去重，同一微信会话顺序处理；桌面已有执行时等待其完成。
- 复用现有 Agent，只发送一条最终文字回复；桌面可以查看对应微信会话。敏感记忆候选仍由桌面确认，微信会提示查看。
- 语音、图片和文件返回文字能力说明，不交给模型处理；微信内入口名称和头像能否自定义尚未验证。
- 扫码连接成功即默认开启「到期提醒同时发送到微信」，仍可在设置中单独关闭。发送循环每 2 秒检查到期通知，不受收件长轮询或模型处理阻塞；桌面已读不影响微信投递。
- 接收中断会退避重连。会话错误 `-2` 的投递等待本人新消息后再尝试；其他发送失败保留记录。
- 独立记录待发、发送中、微信接口接受、失败、等待互动和结果未知。接口接受不等于手机已收到或阅读；发送超时或进程中断不自动重发。
- 取消提醒会取消尚未发送的对应微信投递。暂停和解绑会停止后台任务；解绑清除凭据并取消待发消息。

## 接入位置

| 文件                                         | 职责                                           |
| -------------------------------------------- | ---------------------------------------------- |
| `backend/app/wechat.py`                      | 扫码、本人绑定、长轮询、去重、发送、恢复及状态 |
| `backend/app/main.py`                        | 微信连接管理接口与后端生命周期                 |
| `backend/app/agent.py`                       | 现有对话、工具与最终回复保存                   |
| `backend/app/reminders.py`                   | 原有到期通知与发生时间去重，微信读取其结果     |
| `backend/app/config.py`                      | 现有系统凭据存储                               |
| `backend/migrations/versions/0003_wechat.py` | 新增 3 张渠道状态、收件去重和投递表            |
| `src/components/WechatSection.tsx`           | 扫码、开关、暂停、解绑和最近投递界面           |

当前调用链：微信消息 → 本人校验及去重 → 对应对话 → 现有 Agent → 最终回复 → 微信投递记录。

协议采用客户端主动发起的 HTTPS 长轮询和发送请求，因此判断本机方案无需额外开放入站端口；这是工程推断，仍需微信端到端测试。本机 API 继续只监听回环地址。[腾讯协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)

## 验证结果

- 后端测试覆盖本人限制、消息去重、凭据不返回、提醒去重及取消、会话失效、发送结果未知、重启恢复和旧数据库升级保留对话。
- 前端 13 项测试通过，覆盖默认不连接、主动申请二维码和明确开启微信提醒。
- 浏览器隔离验证使用真实本机后端读取默认状态，以模拟响应验证二维码展示、提醒开关、暂停和解绑；1280px 与 720px 页面无脚本错误或横向溢出。
- 前端构建、Rust 检查及新增 Python 文件静态检查通过。验证证据在 `.local-data/wechat-review-20261016/`。
- 未验证原生扫码、真实模型回复、微信平台兼容或手机收件；未制作新的安装包。

## 本人扫码后的验收

1. 发一条文字并收到小汐回复，检查桌面可看到对应会话。
2. 创建一条短时提醒，在手机确认实际收到，桌面保留同一提醒。
3. 分别检查长时间不互动、授权失效、暂停、解绑、电脑关闭和恢复后的行为；失败必须可见。
4. 若以后改为云端，再验证电脑关闭时仍可使用，以及服务重启不会重复发送。

隔离测试证明本机程序流程，不代表微信实机收发成功。
