## 已发现并处理的问题

1. 项目栏与错误提示叠在消息上：将浮动输入区改为参与纵向布局的底部输入区，项目选择栏放入输入框顶部，修正窄窗口层级。
2. 已结束复杂任务恢复时，未提交的规范化更新与另一个会话写入回执冲突：先完成事务再发布完成状态，相关回归通过。
3. 计划单次覆盖记录中 JSON null 仍可能被 SQL 的非 NULL 条件选中：提醒合并和关闭提醒时按空字典处理，编辑、完成、取消相关用例通过。
4. 搜索连接错误缺少具体类别：返回连接失败分类与重试标记，避免仅落为通用工具错误。
5. MCP/技能菜单切换时旧菜单关闭后的焦点恢复可能关掉新菜单：切换时抑制旧菜单的恢复焦点，正常关闭仍保留焦点行为。
6. 新增拖入项目/重命名的异步回调可能使用旧选中对话：完成请求时按最新选择判断，新增慢请求浏览器用例通过。
7. 测试维护：更新学习信息完整性、第一人称记忆规范化、聊天删除后的受管附件清理、图片生成独立配置、数据库版本、文件 input、课程折叠区及已变化按钮的旧预期；补齐测试 DOM matcher 和模拟 API 返回结构。隔离浏览器运行可通过 `BAI_QA_DATA_MARKER` 校验当前专用目录，原有独立场景目录仍可使用。

## 历史浏览器未通过项及边界

首轮历史全量的 35 个失败不能全部简单归为应用缺陷，也不能全部排除为无效用例。已确认存在以下原因，部分对应场景已在上述 21 项当前流程中修订并复验：

- 旧学习流程缺少新增必填基础、未先展开作答区、仍点击已移除的“下一个知识点”；旧日历标签及时间/标题顺序也已变化。
- 旧场景仍查找已移除的内联头像、旧连接按钮、旧版资料下载区域或不存在的控件；向添加附件按钮执行 `setInputFiles` 会失败。
- 多个历史场景共享后端时，已有项目、记忆、MCP 服务、计划或手动记忆模式会破坏其“空白状态”假设；部分 Embedding 场景依赖独立模拟端口和预置的向量记录。
- 仍保留未逐项完成当前版本复验的历史场景，包括部分语义检索、模型编辑与键盘焦点、旧重复计划交互和窄窗口布局断言。完整失败清单、断言及超时详情保留在首轮日志中。这些模块的后端测试通过不能替代浏览器界面通过。

首轮跳过的图片稳定性用例缺少 `BAI_FEEDBACK014C` 开关。之后单独启用并执行时，暴露其依赖旧 QA 会话的前置条件；将会话与图片响应夹具改为浏览器内自包含后，该用例复验通过。首轮的 1 项跳过仍作为当时状态保留，不回写为当时已经通过。
