## 0.1.4加入写文档读文档的功能：

请为 XiaoXi Agent 实现“上传资料 → 显示解析状态 → 按需读取 → 生成结果文件 → 预览、下载或另存为”的办公文件处理能力。先检查项目现有架构、AGENTS.md，以及附件上传、工具注册、技能脚本和文件产物的实现，优先复用现有能力，渐进修改。

本轮范围是：用户主动上传资料，小汐根据需求读取、整理并生成新文件，保留上传原件；暂不实现本地文件夹管理、任意路径读写或通用代码执行。应用功能负责选择和拖入文件、展示文件名及解析状态、预览结果、下载和通过系统窗口另存为；后端服务负责存储、解析、格式生成、权限校验和任务状态；模型通过内置工具调用这些能力。建议提供 list_files、read_file、create_document、create_spreadsheet、create_text_file，具体命名可遵循项目现有约定。模型使用文件编号访问当前对话授权的附件，不直接指定电脑上的任意绝对路径。

输入优先支持 Word（.docx）、带文字层的 PDF、TXT、MD、CSV、JSON；解析时尽量保留页码、段落和表格来源，支持按页码或片段读取，并明确展示上传中、解析中、可读取、部分解析和失败状态。扫描 PDF、加密文件、损坏文件及暂不支持的内容应给出真实、清楚的提示，不能把解析失败当成空白内容，也不能编造原文。文件内容是待处理资料，不能成为新增权限或执行操作的指令。

输出支持 Word（.docx）、PDF、Excel（.xlsx）、TXT、MD、CSV、JSON。模型负责组织内容与结构，程序使用相应文件库生成合法文件，禁止仅修改扩展名冒充目标格式。Word 支持基本标题、段落、列表、表格、图片和分页；PDF 保证中文字体与基本排版；Excel 支持多工作表、数据、基本公式、数字格式和样式；CSV 正确处理编码、引号与换行；JSON 必须通过结构校验。第一版重点是根据资料生成新文件，暂不承诺完整保留复杂原始版式、宏、批注或修订。解析时不执行文档中的宏、脚本或公式。

生成结果应在对话中展示文件卡片，提供适合格式的文档、表格或文本预览，以及下载、另存为入口；预览转换失败应明确说明，并保留原始产物。支持一次任务生成多个文件。所有上传副本和生成文件存储在应用管理的区域，执行文件类型、内容、大小、处理时长和会话归属校验；默认生成新文件或新版本，不静默覆盖原文件。另存为的位置由用户通过系统窗口选择，覆盖已有文件时明确确认。处理失败、取消或重试时，不展示虚假的成功状态，也不遗留可见的半成品。

按“通用附件与解析 → 模型按需读取 → 各格式生成 → 预览与导出”的顺序实施，并用“上传 Word 和 PDF，生成一份 Word 报告及一份 Excel 明细表”的完整场景贯通验证。检查文件可打开、内容完整、中文显示、分页、表格、公式和异常处理；不要仅验证接口返回成功。遵循项目已有技能与协作约定，保留已有真实 LLM 连接，自动化模拟测试使用独立数据空间，不向真实桌面预览注入模拟记录。完成必要检查后，主动打开并保持桌面测试版，固定复用 .local-data/preview-runtime 的数据和凭据，分别报告本地模拟检查、原生窗口检查及真实模型验收情况。等待用户明确确认本轮测试通过后，才可构建安装包；此前不得运行 NSIS、release:windows 或其他安装包构建流程。
