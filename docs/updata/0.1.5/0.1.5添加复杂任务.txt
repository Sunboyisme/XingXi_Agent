# XiaoXi 复杂任务能力优化计划

## 一、目标与已确定的交互

让 XiaoXi 自动组织多步骤任务，保存中间成果，支持执行中补充要求和中断后继续。

- **全自动进入**：在现有聊天框表达需求，由模型识别并规划，不增加手动模式开关。普通问答和简单工具请求继续使用现有流程。
- **覆盖全部现有工具**：内置工具、文件生成、生图、MCP、Skills、记忆、日历和学习工具统一接入任务执行机制，沿用已有开关与授权。
- **支持执行中补充**：新消息先保存，当前工具调用结束后处理补充要求，再执行后续操作。
- **重启后等待继续**：恢复任务和成果，收到“继续”等明确指令后才重新调用模型或工具。
- 复用现有 Agent、SQLite 和流式事件机制；第一版由一个执行器顺序推进步骤。

## 二、任务组织与持久化

### 自动识别和规划

使用当前选定的聊天模型识别普通请求、新任务、继续任务及修改要求；多阶段交付自动建立任务。识别和规划产生的调用纳入用量统计。

每个任务保存目标、约束、输入资料、预期成果、完成条件和模型选择。步骤保存依赖关系、状态、来源引用和输出摘要。关键信息缺失时提问，信息充分时直接执行。

### 按步骤执行和保存

新增任务、步骤、操作记录三类持久数据，通过增量迁移保留现有数据。每次运行关联稳定任务编号，继续执行时创建新的运行记录，并复用该任务的历史成果。

执行器按依赖顺序推进；每次工具调用前保存操作编号，调用后保存实际结果、产物编号及错误。步骤完成必须有对应结果，不能仅依据模型的完成声明。

任务上下文使用已保存的要求、来源和步骤成果；长资料按需读取。文件沿用现有产物区，原始附件不覆盖，修改后的文件保留新版本。

### 执行中调整

补充消息按到达顺序处理，在下一次工具调用前更新任务版本并重新规划。保留仍然有效的成果，只重做受影响的步骤及其后续步骤。

工具执行绑定明确的任务版本和用户消息，避免运行中新增消息改变当前操作的授权依据。已完成的外部操作保留真实记录，不因重新规划而被当作尚未执行。

## 三、恢复、重复操作与完成判定

- **已完成操作**：通过稳定操作编号复用结果，区分续跑与用户新提出的重复请求；引用产物前检查文件仍然存在。
- **读取和计算**：临时失败最多自动重试一次，再失败则保存进度并说明原因。
- **本机写入和文件生成**：补齐跨运行的操作去重，结合业务记录或产物判断是否已经完成。
- **生图、MCP、技能脚本**：调用中断且结果不明时先核对已有结果；无法核对则暂停并说明，不能把“继续任务”当作重新提交该操作的授权。MCP 和脚本默认不作可安全重试的假设。
- **停止与重启**：停止后保留成果；服务重启时将未完成任务恢复为暂停状态，并区分明确失败与结果未知，不自动重发外部操作。
- **等待用户**：缺少信息、需要沿用已有确认流程或结果无法核实时，任务进入等待状态；收到答复后继续。
- **交付核对**：按完成条件核对实际文件、操作记录和资料来源。存在未完成的必需步骤时，明确展示已完成与待处理内容，不标记整个任务完成。

沿用现有单次运行的时间限制和工具自身限制；超时后保留进度，等待用户继续。

## 四、聊天界面与接口

聊天中增加可展开的任务卡，显示任务目标、当前步骤、已保存成果、等待原因和继续入口。详细工具记录仍可展开查看，不显示虚构百分比。

复杂任务运行时允许发送文字及附件，输入区提示“补充当前任务要求”，保留停止操作。补充提交后显示“已收到，当前步骤结束后处理”，不另开并发执行器。

接口调整：

- `RunRead` 增加可选的 `task_id`；任务状态与单次运行状态分别保存。
- 新增会话任务列表、任务详情、继续和结束任务接口。
- 现有消息接口支持保存执行中的补充消息；自然语言“继续”与任务卡入口使用同一恢复逻辑。
- 现有 SSE 增加任务、步骤和要求更新事件，携带任务编号及版本；重新打开对话后从持久数据恢复展示。

保留普通聊天、学习流程及现有微信文字收发兼容。微信复用任务执行与最终文字回执，完整步骤和文件在桌面查看。

## 五、实施顺序与验收

按以下顺序完成本轮优化：

1. **任务数据与执行基础**：迁移、自动识别、规划、步骤保存和统一操作记录。
2. **工具恢复与去重**：接入全部现有工具，处理成功复用、失败、结果未知和权限变化。
3. **聊天交互**：任务卡、实时状态、执行中补充及自然语言继续。
4. **交付整理**：完成核对、数据导出导入兼容、更新说明及验收步骤。

重点验收场景：

- 普通问答正常；多阶段请求自动建立任务。
- 多份资料生成 Excel 和 Word；Word 失败后继续，保留已有 Excel。
- 生成图片成功后聊天连接断开，继续时展示原图，不重复生成。
- MCP 或脚本结果未知时暂停核对，不重复执行。
- 执行中修改预算，只更新受影响的计算和报告。
- 重启后进度和文件仍在，等待用户说“继续”。
- 任务执行期间关闭工具或撤销脚本授权，后续调用立即遵守当前设置。
- 已有日历、记忆及学习确认规则继续生效；历史对话与数据导出导入保持兼容。

按项目约定，本轮默认由用户测试验收，不主动运行自动化测试、模拟检查、真实模型或桌面验收，不启动测试版、不构建安装包。完成后交付修改清单、行为变化和待验证事项，并追加记录到 `docs/updata/0.1.5/changes.md`；本轮先保持现有版本号。
