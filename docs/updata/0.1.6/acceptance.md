# 0.1.6 人工验收清单

以下为待用户执行的检查步骤，不表示已经通过。当前只进行了类型、语法静态检查与源码审阅；未启动测试版、调用模型、发送微信测试消息或构建安装包。

## 聊天、任务与日期

1. 观察生成过程及历史思考入口，确认显示“正在输出想法”“想法”。
2. 查看一项多步骤任务：需求、步骤编号与状态、完成条件和操作记录应易于区分，展开后不重复显示当前步骤。
3. 完成日历任务后继续说“这个计划不好，帮我删掉吧”或提出具体修改，应继续处理或列出真实候选，不回复“无需继续执行”。只说“继续”应保留已有结果，不重新创建计划。
4. 在北京时间 24、25、26 日各有不同计划时，要求“将25号的计划去掉”，核对仅 25 日发生改变；再明确恢复该计划，核对原编号与 25 日时间恢复，24／26 日不变。注意 25 日早间时间在 UTC 可能仍为 24 日。
5. 对包含多个日期的要求，例如“恢复25号的，删除26号的”，核对两项动作各自的对象；对日期或对象不清楚的要求，应先显示实际候选，不能猜测执行。
6. 重复事项应区分取消本次、修改本次、后续和整个系列；没有明确系列授权时不扩大范围。已查询后再在另一处修改同一记录，应提示刷新核对。
7. 查看完成回复，应有实际结果、具体时间或关键变化和日历入口，不能用工具审计文字代替安排，也不能因为摘要截断推断未展示部分已经创建。

## 记忆与学习

1. 分别打开一行和多行记忆的详情，检查完整内容、分类、更新时间、来源原话及编辑／删除。卡片不再额外显示来源展开块。
2. 通过聊天表达“记一下我喜欢打羽毛球”，确认内容为简洁事实，来源仍保留用户原话；同时核对“不喜欢”“暂时”“每周日”等限定没有被改反或移除。
3. 点击“一键整理表述”，确认打开对比尚未改写任何记录，取消或取消勾选不会保存。保存所选项后检查内容、来源及检索更新；另一处已修改的记录应提示冲突，不覆盖新版本。
4. 模型连接结果条应上下留白一致。这里只检查用户自行触发连接后的显示，不需要为本清单额外提交真实模型请求。
5. 学习页顶部只有紧凑返回、目录和进度，知识点正文标题继续保留。首次进入练习区默认收起，展开后没有多余标题或图片占位提示。
6. 输入草稿并加入图片后反复收起、展开、切换知识点再返回，核对草稿不丢失；收起时拖入图片应展开显示附件。提交失败或停止时草稿应保留，提交成功后沿用原来的进度保存。

## 月历

1. 拖动一个非重复计划到目标日期，检查实际日期、时间、跨日跨度、状态与提醒偏移。拖动跨日计划的中间一天时应整体平移原范围。
2. 重复计划不支持拖动；无效落点或未移到其他日期不写入。发生保存失败时原位置应保留并显示错误。
3. 同名、同时间配置、同状态的相邻日计划应连成视觉带。周日到周一换行显示延续标识，隔天中断；不同状态、不同时间及同一天的独立事项不能重叠冒充一个计划。
4. 连条中点击某一天应打开当天的实际记录；拖动独立日记录只移动那一条。更多事项、农历、日常重复汇总与周历继续可用。
5. 当天事项弹窗直接删除普通计划后，检查计划及未触发提醒被取消；重复事项只取消本次，其他日期保持原规则。

## 微信

1. 核对绑定、收件连接、提醒开关、发送准备四项各自清楚。绑定成功但尚未完成收件连接时不能提前显示“已连接”。
2. 断线、恢复、暂停、登录失效时核对状态、对应错误及最近成功时间。收件恢复不能将某条失败或未知投递改为成功。
3. 主动在微信给 XiaoXi 发一条文字后，点击“发送测试消息”，在手机确认收到固定测试文字。该按钮不会调用模型，接口接受只表示接口结果；手机实际收件仍由本人确认。
4. 点击发送期间不应重复入队；请求响应丢失后重试复用同一请求号。历史“送达结果未知”继续保留，旧记录缺少具体原因时明确说明无法回溯。
5. 新失败记录应区分接口拒绝、HTTP、连接、读写超时、无效响应和中断，诊断中不显示密钥、令牌、请求正文或完整响应正文。

## 交付约定

测试版仅在用户明确要求时准备，固定复用 `.local-data/preview-runtime` 的真实连接、数据与凭据，并保持独立应用标识。本轮安装包需等待用户明确验收通过及当次打包授权。本轮未推送，沿用既有每日推送任务。
