# 记忆保存与确认

默认使用“自动记忆”。记忆页的下拉菜单即时切换模式；连接与设置也能修改保存方式。

| 内容 | 自动记忆 | 每次确认 |
| --- | --- | --- |
| 当前对话、任务结果 | 保留在当前对话 | 保留在当前对话 |
| 用户明确要求记住 | 直接生效 | 直接生效 |
| 用户主动表达、明确且稳定的普通偏好 | 自动生效，可撤销 | 待确认 |
| 健康、财务等私密信息；需要核实的推测 | 待确认 | 待确认 |
| 非明确要求保存的个人事实、项目状态 | 待确认 | 待确认 |
| 当天安排、一次性要求、暂时情绪 | 跳过长期记忆 | 跳过长期记忆 |

明确的“记住”已包含用户授权。明确拒绝记住时跳过。密码和密钥不经聊天工具写入个人记忆。

## 对话中的反馈

- 成功保存时显示“已记住 · 撤销”；更新旧信息时显示“记忆已更新 · 撤销”。提示在 8 秒后关闭，鼠标悬停、键盘聚焦、撤销进行中或出错时暂停关闭。
- 待确认信息在当前对话和记忆页显示同一条确认卡片，支持记住、忽略和查看来源。刷新或重启后仍可处理。
- 只有 `confirmed` 进入后续对话及教学背景和记忆查询工具；`candidate` 存为待确认提议，不作为个人背景使用。
- 记忆页支持搜索、编辑、删除、来源原话查看。删除记忆与删除历史对话分开；当前会话中已经出现的消息仍可能被模型看到。

## 写入路径

`agent.py` 在正常工具循环中发现值得复用的信息后调用 `remember`，不增加单独的后台模型请求。`memory.py` 在服务端决定是否直接生效、提议确认或跳过。模型提供分类与总结，服务端同时检查当前用户消息中逐字引用的 `evidence`，以及明确授权、常见私密信息与临时信息规则。网页、助手输出不能单独作为写入证据。

语义识别依赖所配置模型的工具调用与分类质量；关键词检查提供额外保护，不能穷举所有敏感或临时表达。用户可选择“每次确认”。此版本不对旧对话批量提取记忆。已生效记忆可以建立语义索引，向量保存在同一 SQLite 的 memory_vectors 表，不另设向量数据库服务。

每条聊天记忆保留来源会话、来源消息、原话、待确认原因及版本。候选内容无须每轮重复创建；逐字相同内容去重，语义近似项由模型查询后判断。

## 纠正与撤销

用户纠正偏好时，Agent 查询已有记忆并传 `replaces_id`。直接更新时沿用原记录；需要确认的更新作为独立提议，原记忆继续生效，确认后才替换。确认时检查原记忆版本，避免旧提议覆盖后来的编辑。

每次聊天写入生成 `memory_changes` 记录。撤销新记忆会移除当前记忆；撤销更新会恢复之前的内容与来源。若记录后来已经改变，撤销返回 409，提示去记忆页管理。撤销、忽略或删除后的同一用户消息重试不会重新写入相同内容。历史消息、工具审计与变更记录独立保存，均不属于有效记忆查询范围。

数据库迁移 `0002` 给现有设置增加默认自动模式，并增加来源、版本与变更记录；现有记忆内容、来源、状态不变。

## 0.1.3：查找范围与透明度

每轮聊天先根据最新用户消息查找已生效记忆，最多选 5 条、约 1500 token；未启用 Embedding 或接口不可用时按文字匹配。开启后结合关键词与语义相似度排序。候选、忽略和已删除内容不进入个人背景。向量是记忆页中已生效内容的数字索引，没有另一套隐藏记忆；编辑和删除后旧索引立即失效。

“这次参考的记忆”展示当时保存的记录，打开窗口不重新查询数据库中的当前记忆，也不重新调用 Embedding。技术分数折叠显示。聊天原文、长对话摘要和学习记录是另外的数据，并非记忆页中的长期记忆。
