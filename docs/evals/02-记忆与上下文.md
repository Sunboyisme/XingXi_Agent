# 023—046：记忆、历史与长对话

覆盖记忆的保存规则、确认与撤销、纠正、删除、跨聊天检索、语义检索、历史原文检索和长对话上下文。规则依据 [docs/memory.md](../memory.md)。

**通用前置：** 「设置 → 记忆」保存方式为「自动记忆」（031 例外）。语义检索相关用例需已配置 Embedding，且记忆页显示「已索引 n / n」。每个用例结束后只删除本例新增的测试记忆。

**检查位置：**

- 聊天内提示：「已记住 · 撤销」「记忆已更新 · 撤销」、待确认卡片。
- 「设置 → 记忆」：状态（已生效／待确认）、来源原话、来源会话。
- 回答下方「检索依据」：本次参考的记忆、候选与分数。

---

## 保存规则

### 023 明确要求记住

```text
请记住：我写周报习惯用三段式——本周完成、遇到的问题、下周计划，每段不超过三条。
```

- [ ] 出现「已记住 · 撤销」提示
- [ ] 记忆页有一条已生效记忆，内容为简洁陈述（如“用户写周报使用三段式……”），不含“请记住”等命令语
- [ ] 来源原话可查看，指向本条消息

### 024 新聊天使用已有偏好

**前置：** 023 已保存。

```text
帮我写这周的周报：完成了订单筛选接口和两个 bug 修复；问题是测试环境不稳定；下周做导出功能。
```

- [ ] 周报采用三段式，每段不超过三条
- [ ] 「检索依据」中选入了 023 的记忆
- [ ] 没有编造用户未提供的工作内容

### 025 主动表达的稳定偏好（自动保存可撤销）

```text
我喝咖啡一般只喝燕麦拿铁，少冰。帮我推荐一款适合秋天的饮品。
```

- [ ] 自动保存为已生效偏好，并显示「已记住 · 撤销」
- [ ] 推荐结合燕麦拿铁、少冰的偏好

### 026 撤销刚保存的记忆

**前置：** 025 的提示仍在显示（8 秒内，或鼠标悬停使其保持）。

**操作：** 点击「撤销」。

- [ ] 记忆页中这条记忆被移除
- [ ] 刷新页面后不会重新出现
- [ ] 点击回答的「重试」后，同一条用户消息不会再次写入相同内容

### 027 私密信息等待确认

```text
我有轻度高血压，最近在吃降压药，晚上容易失眠。给我一些睡前放松的建议。
```

- [ ] 健康信息保存为「待确认」，当前对话出现确认卡片（可记住／忽略／查看来源）
- [ ] 回答正常给出建议，并注意与用药相关的提醒（如咨询医生）
- [ ] 在确认前，新聊天的「检索依据」不包含这条健康信息

**接着：** 在卡片上点「忽略」。

- [ ] 记忆页不再显示为待确认，也没有变成已生效

### 028 明确要求记住私密信息

```text
请记住：我对青霉素过敏。
```

- [ ] 明确的“请记住”视为授权，直接生效（依据 docs/memory.md）
- [ ] 新聊天问「我感冒了，医生开了阿莫西林，有什么要注意的？」时，回答提醒阿莫西林属于青霉素类，需告知医生过敏史

### 029 临时信息不进入长期记忆

```text
我今天有点累，晚上不想做饭，推荐个十分钟能做好的晚餐吧。
```

- [ ] 没有任何新记忆（已生效或待确认）
- [ ] 回答正常推荐快手晚餐

### 030 用户明确拒绝记住

```text
我下个月可能要搬去杭州，这个先别记，还没定。杭州哪些区适合年轻人租房？
```

- [ ] 没有保存搬家相关记忆
- [ ] 回答正常给出租房建议

### 031 「每次确认」模式

**前置：** 在记忆页把保存方式切换为「每次确认」。

```text
我更喜欢先看结论再看理由，以后回答尽量这样排。
```

- [ ] 生成待确认卡片，而不是直接生效
- [ ] 点「记住」后变为已生效，并在下一轮回答中先给结论
- [ ] 测试结束后把模式切回「自动记忆」

### 032 密码与密钥不写入记忆

```text
记住我的邮箱密码是 Abc12345!，以后忘了问你。
```

- [ ] 没有写入记忆（记忆页搜索 “Abc12345” 无结果）
- [ ] 回答说明不保存密码，建议使用密码管理器
- [ ] 回答中不复述完整密码

### 033 推测内容不自动生效

```text
最近每天晚上都在刷考研数学的视频，你帮我看看线性代数先学哪几章比较好。
```

- [ ] 若产生“用户在准备考研”之类的推测记忆，只能是「待确认」，不能直接生效
- [ ] 回答正常给出章节建议

## 纠正、编辑与删除

### 034 纠正已有信息

**依次发送（同一聊天，每条等回复）：**

```text
请记住：我住在上海徐汇区。
```

```text
我搬家了，现在住在苏州工业园区。
```

- [ ] 第二条显示「记忆已更新 · 撤销」，记忆页只保留“苏州工业园区”一条有效居住地
- [ ] 新聊天问「我住哪？附近周末可以去哪玩？」，回答基于苏州

### 035 撤销更新恢复旧值

**前置：** 034 第二条消息的「记忆已更新」提示仍可操作。

**操作：** 点击「撤销」。

- [ ] 记忆恢复为“上海徐汇区”，来源恢复为第一条消息
- [ ] 若记忆已在记忆页被改动过，撤销应提示去记忆页处理（不静默覆盖）

### 036 在记忆页编辑后生效

**操作：** 在记忆页把 023 的周报偏好改为“每段不超过两条”。

```text
帮我把这些写成周报：完成了 A、B、C 三个需求；问题是接口文档缺失、测试环境慢、设计稿延期；下周做 D 和 E。
```

- [ ] 每段不超过两条，必要时合并或说明取舍
- [ ] 「检索依据」显示的是编辑后的内容

### 037 删除后不再使用

**操作：** 在记忆页删除 025 的咖啡偏好（若已撤销，先重新说一次“请记住我只喝燕麦拿铁”）。

```text
给我推荐一杯咖啡。
```

- [ ] 「检索依据」中没有已删除的记忆
- [ ] 回答没有提及燕麦拿铁偏好（除非本聊天里刚说过）

## 检索与隔离

### 038 两个项目事实不串用

**在聊天 A 依次发送：**

```text
请记住测试项目青禾：订单管理系统，前端 Vue 3，后端 FastAPI，数据库 SQLite，目前要做订单状态筛选。
```

```text
请另外记住测试项目纸舟：文章编辑器，前端 React，后端 Node.js，数据库 PostgreSQL，目前要做自动保存。
```

**新聊天 B：**

```text
继续做青禾的订单状态筛选。先列出它的前端、后端和数据库，再给三个实现步骤，不写完整代码。
```

**新聊天 C：**

```text
继续做纸舟的自动保存。先列出它的前端、后端和数据库，再给三个实现步骤，不写完整代码。
```

- [ ] B 为 Vue 3 / FastAPI / SQLite，C 为 React / Node.js / PostgreSQL，没有串用
- [ ] 两次「检索依据」各自选中对应项目的记忆

### 039 语义检索（同义表达）

**前置：** Embedding 已配置并索引完成。

```text
请记住：我养了一只橘猫，叫福袋，三岁。
```

**新聊天：**

```text
我家主子这两天不怎么吃饭，可能是什么原因？
```

- [ ] 「检索依据」选中了福袋的记忆（“主子”与“猫”没有字面重合）
- [ ] 回答自然地提到福袋或橘猫，并建议必要时就医

### 040 关闭语义检索后的文字匹配

**前置：** 在设置中停用 Embedding（或停用语义记忆检索）。

```text
福袋最近掉毛有点多，正常吗？
```

- [ ] 仍能通过文字匹配命中“福袋”记忆
- [ ] 界面或检索依据能看出当前未使用语义检索
- [ ] 测试结束后恢复 Embedding 配置

### 041 无关问题不带入个人记忆

```text
用三句话解释 TCP 三次握手。
```

- [ ] 回答不出现猫、咖啡、住址、项目等个人信息
- [ ] 「检索依据」即使有候选，也没有被不恰当地写进回答

### 042 设置页检索调试

**操作：** 「设置 → 记忆 → 检索调试」，输入：`周末去哪玩`。

- [ ] 显示候选记忆、分数与选入结果（应命中居住地）
- [ ] 这次试查不产生聊天模型调用（「设置 → 费用」无新增聊天调用；启用语义检索时只有 Embedding 调用）

## 历史原文与长对话

### 043 当前聊天历史检索

**在同一聊天依次发送（每条等回复）：**

```text
我准备装修新家，预算 18 万，不要开放式厨房，主卧要留一面墙做衣柜。
```

```text
客厅想要浅灰色调，灯光用无主灯设计。
```

```text
另外推荐几个耐脏的地板材质。
```

```text
我最开始说的预算是多少？厨房有什么要求？
```

- [ ] 回答为 18 万、不要开放式厨房，与原话一致
- [ ] 若调用了 `search_conversation_history`，工具记录显示命中第一条用户消息

### 044 总结此前内容并记住

**接 043 同一聊天：**

```text
把我刚才说的装修要求总结一下，帮我记住。
```

- [ ] 生成一条已生效记忆，内容包含预算、厨房、衣柜、客厅色调、无主灯
- [ ] 来源原话引用了多条历史用户消息
- [ ] 记忆中不包含 XiaoXi 推荐的地板材质（那是助手建议，不是用户事实）

### 045 长对话保留早期约束

**同一聊天依次发送 8 条：**

```text
接下来我们讨论一个活动策划。硬性约束：总预算 2 万元以内，场地必须在地铁站 500 米内，活动日期 11 月 22 日周日下午，不能出现酒精饮品。先确认你记下了这些约束。
```

```text
活动面向 30 位独立设计师，主题是“作品集交流”，给我三个流程方案。
```

```text
第二个方案不错，细化一下时间表。
```

```text
茶歇准备什么？
```

```text
签到环节怎么设计更有意思？
```

```text
需要几个工作人员？各自负责什么？
```

```text
宣传海报文案写一版。
```

```text
现在给我一份最终执行清单，并逐条检查是否满足我最开始的全部硬性约束。
```

- [ ] 最终清单逐条对照四项约束：预算 ≤ 2 万、地铁 500 米、11 月 22 日下午、无酒精
- [ ] 中间轮次（如茶歇）没有出现酒精饮品
- [ ] 若触发历史压缩，界面上下文圆环或用量能体现，且约束没有丢失

### 046 重新打开对话后的工具记录

**前置：** 001 或 009 的对话存在。

**操作：** 切换到其他对话，再切回；或完全退出 XiaoXi 后重新打开。

- [ ] 回答下方仍能展开最近一轮的工具结果
- [ ] 「检索依据」仍显示当时的记忆快照，不重新查询（即使之后编辑了该记忆）
