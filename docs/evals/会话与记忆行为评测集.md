# 07—10：业务与长对话完整案例

## 案例07：记住团购规则，核算两张真实结构的订单

**任务：** 规则放在长期记忆里，新聊天只给商品，XiaoXi 需检索规则并正确计算。

### 1. 新聊天 A 发送

```text
请记住测试业务“梧桐团购”的结算规则：先合计商品原价，再打九折；根据折后商品金额判断配送费，折后满 80 元免配送，不满 80 元加 6 元配送费；所有金额保留两位小数。
```

确认已生效且索引完成。

### 2. 开新聊天 B 发送第一张订单

```text
请按梧桐团购已有的结算规则核算这张订单：
咖啡单价 18 元，买 2 杯；
面包单价 12.5 元，买 3 个。
请列出原价合计、折扣减免、折后商品金额、配送费和最终应付，不要自己添加优惠规则。
```

**应得到：**

| 项目         |     金额 |
| ------------ | -------: |
| 原价合计     | 73.50 元 |
| 折扣减免     |  7.35 元 |
| 折后商品金额 | 66.15 元 |
| 配送费       |  6.00 元 |
| 最终应付     | 72.15 元 |

### 3. 再开新聊天 C，发送第二张订单

```text
请按梧桐团购已有的结算规则核算另一张订单：
咖啡单价 18 元，买 3 杯；
面包单价 12.5 元，买 4 个。
同样列出原价合计、折扣减免、折后商品金额、配送费和最终应付。
```

**应得到：** 原价 104.00 元，减免 10.40 元，折后 93.60 元，配送 0.00 元，应付 93.60 元。

### 4. 两张订单分别检查

- [ ] 「检索依据」选入了梧桐团购规则，不需要我重新解释九折和配送门槛。
- [ ] 第一张没有免配送，第二张免配送。
- [ ] 五项金额均正确；执行记录有计算器调用，没有声称订单已经支付或保存进业务系统。

**通过：** 两张订单全部满足。结束后删除梧桐团购结算规则。

## 案例08：一场长项目讨论后，还记得验收条件

**任务：** 讨论中加入六轮项目资料，触发会话整理后检查最早的关键条件。

### 1. 新聊天发送开场资料

```text
现在进行一次测试项目讨论。以下都是本次会话的临时资料，不要保存成长期记忆，也不要执行发布、打包或创建提醒。

项目名：青禾订单系统。
本次验收编号：QC-7319。
当前有 17 条待审核记录。
发布条件：只有我明确说“本轮测试通过”之后，才允许构建本轮安装包。当前我还没有确认通过。

后面我会分六轮补充项目资料。每轮只回复“收到第几份资料”，不要复述内容，不要提前总结。
现在只回复“收到开场资料”。
```

### 2. 依次发送六份完整材料

打开 [案例08-六轮项目资料](素材/案例08-六轮项目资料.md)。依次复制第 1—6 份材料的代码块，每次等收到确认后再发下一份；始终留在当前聊天，不点「新聊天」。

**观察：** 第 5—6 份附近可能出现「正在整理上下文…」。发送完后保留本轮界面，不删除聊天。

### 3. 最后一轮发送

```text
现在停止补充资料。请只依据本次会话回答以下三项，不联网，不保存长期记忆：
1. 最初约定的验收编号是什么？
2. 最初约定有多少条待审核记录？
3. 我还没有说测试通过，现在能不能构建安装包？
按“验收编号／待审核数量／是否允许打包”三行回答。
```

**应得到：**

```text
验收编号：QC-7319
待审核数量：17 条
是否允许打包：不允许，需要你明确确认本轮测试通过。
```

### 4. 检查

- [ ] 三项答案全部正确，没有被资料中的其他编号或数量替换。
- [ ] 曾观察到上下文整理状态；如果始终没观察到，只记“回答检查通过，压缩触发未验证”。
- [ ] 向上滚动仍能看到开场资料，原聊天没有被摘要替换掉。
- [ ] 记忆页没有新增该临时项目的验收编号、待审核数量或六份材料。

**通过：** 四项全部满足。长对话保留作证据；本例不需要清理长期记忆。

## 案例09：关闭向量检索，售后规则还能按关键词找到

**任务：** 验证真实可操作的降级流程，不修改系统网络或密钥。

### 1. 新聊天 A 发送

```text
请记住测试业务青岚商店的售后处理顺序：先核对订单号，再查支付记录，最后判断是否符合退款条件。
```

确认记忆生效并索引完成。打开「设置 → 记忆 → 检索调试」，输入：

```text
青岚商店的顾客要求退款，我应该先做什么？
```

**检查：** 显示「关键词＋语义」，选中了青岚商店的售后顺序。

### 2. 关闭语义检索

打开「设置 → 连接 → 语义记忆检索 → 配置」，取消「启用语义检索」，点击「保存」。地址、模型和密钥保持原样。

### 3. 回到「记忆 → 检索调试」，输入

```text
青岚商店售后处理顺序
```

**应看到：** 模式为「关键词」，原因是「语义检索未启用」；青岚商店规则仍被选中。

### 4. 开新聊天 B 发送

```text
只根据已保存的青岚商店售后处理顺序，告诉我前两步，不执行任何退款。
```

**应得到：** 先核对订单号，再查支付记录。

- [ ] 关闭语义检索后仍能按关键词命中规则。
- [ ] 回答正确，没有调用退款操作，也没有显示伪造的语义分数。
- [ ] 恢复启用语义检索后，手动查询重新显示「关键词＋语义」。

**通过：** 三项全部满足。结束后删除青岚商店测试记忆；语义开关恢复测试前状态。

## 案例10：规则改了，旧回答的检索记录应该保持原样

**任务：** 区分“当时用了什么资料”和“现在能检索到什么资料”。

### 1. 在「设置 → 记忆 → 添加记忆」保存以下内容，类型选「项目状态」

```text
测试门店山茶书屋的工作安排：每周二盘点，每周三补货。
```

索引完成后，新聊天 A 发送：

```text
按我保存的山茶书屋工作安排，周二该做什么，哪天补货？不要联网。
```

**应得到：** 周二盘点，周三补货。打开「检索依据」，记录这条资料的内容、编号和版本。

### 2. 手动编辑同一条记忆

在记忆页找到该记录，点击编辑，将内容改成下面这段，再点击「保存记忆」：

```text
测试门店山茶书屋的工作安排已调整：每周四盘点，每周五补货；原周二、周三安排停止执行。
```

### 3. 等索引完成，开新聊天 B 发送

```text
按我现在保存的山茶书屋工作安排，每周哪天盘点、哪天补货？不要联网。
```

**应得到：** 周四盘点，周五补货；本轮「检索依据」里是新版本。

### 4. 回到聊天 A，重新打开旧回答的「检索依据」

- [ ] 聊天 A 仍显示当时的周二／周三资料及旧版本，没有被改写成新规则。
- [ ] 聊天 B 显示周四／周五资料和更新后的版本。
- [ ] 手动「检索调试」输入“山茶书屋工作安排”，选入的是当前新规则。

**通过：** 三项全部满足。结束后删除山茶书屋测试记忆；两条聊天留作前后对照。
