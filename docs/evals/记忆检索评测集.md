# 01—06：记忆检索完整案例

每个案例从「新聊天」开始；先完成当前案例，再清理它新增的记忆。语义检索案例需等「已索引 n / n」后继续。

## 案例01：换个聊天，还能按我的习惯教 Python

**任务：** 记住学习方式，再换一个聊天学习列表。

### 1. 在聊天 A 发送

```text
请记住我的 Python 学习习惯：先给一段能直接运行的小代码，再用最多三句话解释；例子优先使用待办清单。
```

**检查：** 打开「设置 → 记忆」，应有一条已生效的 Python 学习偏好。若模型只口头说记住、没有实际记录，本步失败。

### 2. 点击「新聊天」，在聊天 B 发送

```text
教我 Python 列表的 append。用读书、散步两个待办开始，再加上写代码。
```

**预期回答可类似：**

```python
todos = ["读书", "散步"]
todos.append("写代码")
print(todos)
```

输出为 `['读书', '散步', '写代码']`，之后用不超过三句话解释。

### 3. 点击回答下方「检索依据」

- [ ] 选中了第 1 步保存的学习偏好。
- [ ] 回答先给代码，再解释，使用待办清单。
- [ ] 列表最终确实包含三个待办，没有声称已在本机运行代码。

**通过：** 三项全部满足。结束后只删除本例新增的学习偏好。

## 案例02：两个项目切换，不能串技术栈

**任务：** 同时管理订单系统与文章编辑器。

### 1. 在聊天 A 依次发送下面两条，每条等回复后再发下一条

```text
请记住测试项目青禾：这是订单管理系统，前端 Vue 3，后端 FastAPI，数据库 SQLite。目前要实现订单列表的状态筛选。
```

```text
请另外记住测试项目纸舟：这是文章编辑器，前端 React，后端 Node.js，数据库 PostgreSQL。目前要实现自动保存。
```

**检查：** 记忆页里能看到两个项目的对应事实；一条合并记录也可以，但项目名与技术栈必须清楚对应。

### 2. 开新聊天 B 发送

```text
继续做青禾的订单状态筛选。先列出该项目的前端、后端和数据库，再给三个实现步骤。不要写完整代码。
```

**应得到：** Vue 3、FastAPI、SQLite；步骤围绕状态筛选参数、接口查询和列表刷新。

### 3. 再开新聊天 C 发送

```text
继续做纸舟的自动保存。先列出该项目的前端、后端和数据库，再给三个实现步骤。不要写完整代码。
```

**应得到：** React、Node.js、PostgreSQL；步骤围绕内容变更、延迟保存、保存接口或状态提示。

### 4. 分别查看两次回答的「检索依据」

- [ ] 青禾问题选入了青禾资料，回答没有将其说成 React / Node.js。
- [ ] 纸舟问题选入了纸舟资料，回答没有将其说成 Vue / FastAPI。
- [ ] 若同时召回另一个项目，也没有把它的事实套在当前项目上；记下多召回情况。

**通过：** 两次回答的项目事实均正确。结束后删除两份测试项目记忆。

## 案例03：花店改了营业时间，旧时间不能继续生效

**任务：** 将测试花店的关门时间从 19:30 更新为 18:00。

### 1. 新聊天 A 发送

```text
请记住测试门店南栀花店：每天 09:00 开门，19:30 关门。这是练习数据。
```

等记忆保存并索引完成，再开新聊天 B：

```text
只根据我保存的南栀花店资料回答，不联网：下午 18:30 去取花，门店还开着吗？
```

**应得到：** 开着，原记录的关门时间是 19:30。

### 2. 在聊天 B 继续发送

```text
南栀花店调整营业时间了。请更新原来的记忆：仍然每天 09:00 开门，但现在 18:00 关门，19:30 这个旧时间作废。
```

**检查：** 记忆页的已生效记录已经更新；若出现待确认的纠正，先点击「确认更新」，再继续。

### 3. 开新聊天 C，再发同一个问题

```text
只根据我保存的南栀花店资料回答，不联网：下午 18:30 去取花，门店还开着吗？
```

- [ ] 回答为已经关门，当前关门时间是 18:00。
- [ ] 本轮「检索依据」选中的有效内容是新时间。
- [ ] 没有另一条仍生效的记录继续把关门时间写成 19:30。

**通过：** 三项全部满足。旧聊天里出现 19:30 属于历史记录，不以此判错。结束后删除花店测试记忆。

## 案例04：删除自提点信息后，换聊天不能继续知道

**任务：** 保存并删除一条仅在测试中出现的自提点。

### 1. 新聊天 A 发送

```text
请记住练习门店云桥书店的自提点：二楼 B 区，绿色柜子旁。这只是测试资料。
```

索引完成后，新聊天 B 发送：

```text
只根据我保存的信息，不联网：云桥书店取书应该去哪个位置？
```

**应得到：** 二楼 B 区，绿色柜子旁。「检索依据」里应出现这条资料。

### 2. 打开「设置 → 记忆」

找到云桥书店这条测试资料，点击它的删除按钮，再点击确认弹窗中的「删除记忆」。其他记录保留。

### 3. 开新聊天 C，不能继续使用聊天 B

```text
只根据我现在保存的信息回答，不联网，也不要猜测：云桥书店的自提点在哪里？不知道就直接说不知道。
```

- [ ] 回答不知道具体位置，没有给出二楼 B 区或绿色柜子。
- [ ] 当前「检索依据」中，没有选入已经删除的云桥书店资料。
- [ ] 聊天 B 的旧回答仍保留，且没有被当前回答当作有效记忆。

**通过：** 三项全部满足。聊天 C 不需要再清理记忆；旧测试聊天可保留作证据。

## 案例05：偏好待确认时不能用，确认后才能用

**任务：** 测试「每次确认」模式的实际效果。

### 1. 准备

在「设置 → 记忆」记录原来的保存方式，然后切换为「每次确认」。本例不要使用“请记住”这样的明确保存指令。

### 2. 新聊天 A 发送

```text
我喜欢在讨论订单业务时先看流程图，再看字段表，这样我比较容易理解。
```

**检查：** 应出现「要记住这条信息吗？」的待确认卡片。先不点击「记住」。若没有生成候选，本步记录失败，不手动补一条已确认记忆。

### 3. 开新聊天 B 发送

```text
只依据我已经生效的个人偏好回答：讨论订单业务时，我喜欢先看哪种内容？如果没有保存过，就说目前不清楚。
```

**应得到：** 目前不清楚；「检索依据」不能选入待确认卡片的内容。

### 4. 回到「设置 → 记忆」，在该候选卡片点击「记住」

等待索引完成，再开新聊天 C：

```text
只依据我已经保存的偏好回答：讨论订单业务时，我喜欢先看哪种内容，再看哪种内容？
```

- [ ] 确认前未选入候选偏好，也未把它说成已知事实。
- [ ] 确认后选入了该偏好，并回答先看流程图，再看字段表。
- [ ] 记忆来源能对应到聊天 A 的原话。

**通过：** 三项全部满足。结束后删除本例的偏好，并恢复原来的记忆保存方式。

## 案例06：有项目记忆时，纯计算也不能乱带背景

**任务：** 检查无关记忆误召回与回答污染。

### 1. 打开「设置 → 记忆 → 添加记忆」，各添加一条并保存

类型选「项目状态」：

```text
测试项目雾桥使用 Vue 3，正在设计仓库货架筛选页面。
```

类型选「偏好」：

```text
在测试项目雾桥的界面中，我喜欢暖灰背景、紧凑按钮和圆角卡片。
```

### 2. 等索引完成，新聊天发送

```text
37 乘以 19 等于多少？只给结果。
```

**应得到：** `703`。

### 3. 检查回答和「检索依据」

- [ ] 结果为 703，没有提到雾桥、Vue 或界面风格。
- [ ] 雾桥两条资料没有被选入本轮上下文。
- [ ] 若算对但选入了无关记忆，分别记录“回答正确、检索失败”，不能整体判通过。

**通过：** 三项全部满足。结束后只删除雾桥两条测试记忆。
