# 复杂任务与执行恢复

在原聊天框直接提出工作要求，无需切换模式。XiaoXi 使用当前选择的模型识别多阶段任务，保存目标、约束、步骤、真实工具结果和文件；自动识别、规划、分步处理和最终核对会增加模型调用与耗时，计入本轮用量。普通请求保留原对话流程；没有已有任务且模型未能返回有效识别结构时，退回普通对话，不声称已经建立持久任务。

任务卡位于对应 XiaoXi 回复的头像和名字下方，显示任务名称、状态与成果，展开后查看真实步骤、具体失败原因及操作记录；历史任务不随无关的新问答移动。卡片不再显示“继续任务／结束任务”按钮和通用续跑说明，复杂任务的暂停／失败状态也不再重复生成一块“这次回答没有完成”提示。修改后的成果分为当前成果和历史成果，上传原件保持不变。

聊天输入区只有一个发送／停止按钮：执行中没有草稿时显示停止，有文字或附件时显示发送。复杂任务执行中发送内容作为补充要求保存，再在当前工具调用结束后调整后续步骤；受影响的步骤重新处理，仍适用的成果保留。普通回答执行中发送新消息会先等待上一轮停止，再提交新消息，避免并发回答；停止或提交期间防止重复操作，失败时保留尚未发送的草稿。

点击停止会暂停执行并保留成果。重启后不自动调用模型或重发工具请求；未完成任务通过聊天发送“继续”恢复，结束任务也通过聊天表达。已完成任务收到继续要求时保持完成状态、展示已有交付，不重新执行工具或提示任务暂停。任务的状态与单次回答状态分别保存；回答已经结束或已经生成文件，不代表整个任务的交付核对已经完成。结束任务保留已有文件，再提出新要求会建立新的执行。

全部现有工具复用原来的开关和授权。已保存的成功结果可复用；查询类临时失败至多自动再试一次。生图、MCP、脚本和本机写入若中断或结果不明，会展示待核实状态，不因“继续”盲目再次执行。用户核对后可标记外部已完成、明确重新提交，或跳过操作。外部完成标记不代表本机已取得文件；缺少所要求文件时任务仍不能标记交付完成。

任务原始步骤和工具结果保留在 SQLite，过长内容只向模型提供标明截断的摘录，可通过内部只读工具按编号取回完整记录。任务及产物参与现有个人数据导出，仍要求数据库版本一致；模型密钥、MCP 连接、技能授权和解释器沿用本机配置。技能的同一任务复用工作目录，写入 `outputs/` 并已登记的文件可以从产物重建；工作目录其他临时内容和第三方运行环境不属于便携数据，不能承诺跨机器恢复任意脚本环境。

复杂任务工具的长结果在保存完整返回内容后，仅向模型发送结构化摘录，带记录编号、原始长度和省略字段路径；短结果、执行错误以及明确请求的文件/技能/记录正文读取不再二次压缩。状态、错误、来源地址、文件编号、分页标记等关键字段保留，精简不增加额外的摘要模型调用，也不改变完整结果的回放、成果核对或权限检查。这里的完整原文指工具实际返回并保存的内容；原工具自身的分页、截断和解析限制仍然保留。

每一步默认只携带直接依赖步骤的成果，以及当前步骤/直接依赖的最多12条操作回执（优先当前步骤，再按新旧排序）。其他步骤保留编号、标题和状态；完整操作目录可按任务编号调用 `read_task_result`，再按步骤或操作编号读取原文。该工具新增 `path`（JSON Pointer，如 `/content` 或 `/results/0/summary`），支持只取所需字段，并使用 `offset`、`count` 和 `next_offset` 分段续读；只能读取当前任务范围内的记录。已有任务的依赖未列全时，仍可从索引找回其他成果。

文件存在性、支持格式的读取和必需产物数量由程序核对，内容覆盖度由模型结合实际成果核对。模型的分析质量和外部平台真实执行结果仍需用户验收。微信继续使用已有文字回执，完整步骤和文件在桌面查看。

## 用户验收场景

1. 上传资料，说“比较两套方案的成本、功能和实施风险，生成 Excel 对比表与 Word 建议书；缺失信息标为待确认”，检查是否自动建立任务、显示实际步骤并交付真实文件。
2. 执行中发送“预算改为五万元”，检查补充已接收、当前调用结束后更新计划，后续结果使用新预算，旧文件标为历史成果。
3. 已生成一份文件时停止任务，之后说“继续”，检查已有文件保留，继续补齐剩余成果。
4. 执行中退出并重新打开 XiaoXi，检查进度仍在、尚未自动续跑；明确继续后再恢复。
5. 生图、MCP 或脚本结果未知时，检查状态与操作记录，核对外部结果后再选择下一步；不应仅因继续任务重复提交。
6. 执行中关闭工具或撤销脚本授权，检查新的工具调用遵守当前设置；已有成果仍可查看。
7. 验证普通聊天、日历确认、记忆确认、学习流程和微信原有文字能力没有被任务状态替代。

本轮仅添加了回归用例源码，未运行自动化测试、模拟检查、桌面检查、真实模型或微信收件验收，也未构建安装包。
