# 办公文件处理

## 使用

在聊天输入区选择或拖入 DOCX、PDF、XLSX、TXT、MD、CSV、JSON，等待“可读取”或“部分解析”后发送需求。每次最多 4 个附件；办公文件单个最多 20 MB，图片仍为 10 MB。上传和解析状态独立显示，失败可重试或移除，失败附件未处理前不会提交。

小汐使用 `list_files`、`read_file` 按编号读取当前对话的资料，按页码或片段继续读取。结果使用 `create_document`、`create_spreadsheet`、`create_text_file` 生成；可在一个任务里生成多个文件。只有真实产物成功保存后，聊天才提供文件卡片。

生成文件支持 DOCX、PDF、XLSX、TXT、MD、CSV、JSON。DOCX 为基本标题、正文、列表、表格、图片、页眉页脚和分页；PDF 可翻页查看实际渲染页面；Word 为内容预览，完整样式以文件为准；Excel 预览生成时的数值缓存。桌面“下载”保存到应用导出目录并打开该目录；“另存为”调用系统保存窗口，用户选择位置，取消不写入文件。浏览器使用标准下载。

## 当前边界

- Word 接受 `.docx`，不接受旧版 `.doc`；不保证保留复杂排版、批注、修订或识别图片中文字。
- PDF 读取有文字层的页面。扫描页明确提示需要 OCR；本轮未实现 OCR。加密文件需要用户先解密。最多解析 150 页、40 万字，截断和缺失有提示。
- 输入 Excel 不执行公式、宏或外部链接。输出支持基础四则运算、SUM、AVERAGE、MIN、MAX、COUNT、ABS、ROUND、单元格及工作表引用；校验循环引用、除零和外部引用。保存时写入计算缓存，Excel 打开后可继续重算。不承诺完整 Excel 函数引擎或复杂模板编辑。
- CSV 为 UTF-8 BOM，处理引号及换行，并将可执行公式样式的文本转为普通文本。JSON 先校验结构。
- 预览按需读取，文本最多展示 100 个片段，表格最多 500 行；下载文件不因预览截断而改变。

## 存储和执行

上传原件以随机编号保存于当前应用数据目录 `attachments/files/*.bin`，和图片附件分开；解析文本与来源保存到 `office_files`。附件随消息绑定对话，工具不能读取其他对话的文件；删除对话后原件及元数据保留，但不再对该对话开放。原件不覆盖，输出保存到现有产物区。便携数据导出/导入已包含新附件目录。

解析、生成和 PDF 渲染使用固定协议的子进程，参数没有任意路径、网络请求或代码执行入口。最多同时 2 个进程，单次 45 秒；Windows 使用进程组和 512 MB 内存上限。输入 ZIP 结构限制解压总量与条目数，并拒绝宏。单个产物最多 20 MB，每轮最多 20 个文件、50 MB；同轮相同请求复用文件。生成失败或取消后不发布半成品。

这是受限的办公文件服务，并非操作系统安全沙箱。现有已授权技能脚本和 MCP 的权限是另外的能力，不会因本文件服务而自动被隔离。用户文件作为资料处理，内容不能授予权限；真正的文件范围由后端校验。读取后的片段会进入当前所选模型的请求，界面会提示。

## 验证

- `python scripts/verify-office-files.py`：在 `.local-data/qa-office` 生成七种格式并重新读取，检查中文 PDF 渲染及 Excel 缓存值。
- `pytest backend/tests/test_office.py`：格式、异常、会话范围、重复生成、原件保留、导出，以及模拟模型组合调用生成多文件。
- `BAI_OFFICE_QA=1 BAI_BROWSER_URL=http://127.0.0.1:5196 pnpm exec playwright test tests/browser/office-files.spec.ts`：仅允许隔离目录，验证上传、状态、模型工具链、预览与下载。
- 原生桌面检查复用 `.local-data/preview-runtime`，不得注入模拟文件、消息或替换真实模型连接。真实模型对资料的理解质量及微信收件另行验收。
